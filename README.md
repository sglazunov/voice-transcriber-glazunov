# 🎙️ Voice Transcriber — распознавание встреч и автопротокол

Локальное веб-приложение, которое превращает **аудио- и видеозаписи встреч** в
**текст**, а затем — в **готовый протокол в Word**: о чём шёл разговор, подробный
разбор по темам, выводы, что уже сделано и какие задачи остались (с
ответственными).

Работает **на вашем компьютере**: запись никуда не отправляется (распознавание —
локальное, на движке faster-whisper). ИИ-анализ для протокола можно тоже держать
локально (Ollama) или подключить облачный движок по ключу.

Запускается двумя способами: как **веб-приложение** в браузере (ветка `main`)
или как **отдельная программа в своём окне** (ветка `desktop`) — см. разделы
ниже.

---

## Для чего это и какие задачи решает

- **Не вести конспект вручную.** Загрузил запись созвона — получил полный текст.
- **Быстро вспомнить, что решили и кто что должен сделать.** Протокол сам выделяет
  решения, задачи и ответственных — не нужно пересматривать часовую запись.
- **Поделиться итогами встречи.** Документ Word можно сразу отправить команде.
- **Сделать субтитры** к видео (формат SRT).
- **Сохранить приватность.** Для конфиденциальных встреч всё считается локально,
  без облака.
- **Расшифровать интервью, лекции, голосовые** — не только встречи.

Типичные пользователи: команды разработки/проектов, аналитики, менеджеры,
журналисты — всем, кому нужно превратить разговор в текст и понятный итог.

## Что умеет

**Распознавание речи**
- Аудио и видео: `mp3, wav, m4a, ogg, opus, flac · mp4, mkv, webm, mov` — до 2 ГБ
  (видео на ~1 ч проходит спокойно; аудиодорожка из видео берётся автоматически).
- Языки: русский / английский / украинский / автоопределение.
- **Живой текст**: реплики появляются прямо во время распознавания, с прогрессом,
  таймером и длительностью.
- Форматы выгрузки: **TXT** (с таймкодами), **SRT** (субтитры), **JSON**.
- **Пауза / Продолжить / Отмена** прямо во время распознавания. При отмене уже
  распознанная часть сохраняется.
- Результаты хранятся на сервере **24 часа** — доступны для скачивания даже после
  перезагрузки страницы (потом авто-очистка).

**Точность имён и терминов**
- Поле «известные имена и термины» (подсказка модели) и глоссарий
  «как слышится → правильно» — чтобы фамилии и термины не искажались.

**Протокол встречи (Word)**
- Структура документа: *О чём шёл разговор → Подробный разбор по темам →
  Ключевые мысли → Выводы → Решения и договорённости → Сделано (выполненные
  задачи) → Задачи (нужно сделать, таблицей с ответственными) → Мелкие задачи →
  Полная транскрипция.*
- **Несколько ИИ-движков** на выбор; протокол каждого движка сохраняется
  отдельным файлом — можно сравнить, какой лучше.
- **Перегенерация** другим движком без повторного распознавания.

**Кто говорил (диаризация)** — опционально, по желанию (см. ниже).

## Как пользоваться

1. Откройте `http://localhost:8000`.
2. Выберите режим:
   - **🎙 Только распознавание** — нужен лишь текст/субтитры.
   - **📄 Протокол встречи** — текст + анализ + Word-документ.
3. (Для протокола) выберите **движок** в списке. Локальный Ollama — бесплатно и
   оффлайн; облачные движки подключаются по ключу в панели «🔑 Подключить API».
4. (По желанию) раскройте **«🎯 Точность: имена и термины»** и впишите имена
   участников и термины.
5. Перетащите файл (или нажмите, чтобы выбрать) → **«Распознать»**.
6. Следите за живым текстом. Готовый результат: кнопки **TXT / SRT / JSON**, а в
   режиме протокола — **«📄 Word · <движок>»**.
7. Не понравился протокол? Смените движок в списке и нажмите
   **«🔄 Перегенерировать»** — появится ещё один документ рядом для сравнения.

Доступ с других устройств в той же сети: `http://<IP-этого-ПК>:8000`
(IP узнать командой `ipconfig` → строка IPv4).

## Как запустить (Windows)

1. Установите **Python 3.12** с https://www.python.org/downloads/
   — при установке отметьте галочку **«Add Python to PATH»**.
   > ⚠️ Именно 3.12. На **Python 3.14** движок распознавания (CTranslate2)
   > падает — он пока не поддерживает 3.14.
2. Двойной клик по **`install.bat`** — создаст окружение, поставит зависимости,
   доустановит Visual C++ Redistributable и скачает модель распознавания
   (один раз).
3. Двойной клик по **`run.bat`** — запустит сервер и откроет браузер на
   `http://localhost:8000`.

Чтобы остановить — закройте окно `run.bat`.

### Если распознавание не запускается (прогресс висит на 0% / окно падает)

- **Нужен Python 3.12**, не 3.14 — пересоздайте окружение на 3.12
  (`py -3.12 -m venv .venv`).
- **Нет Visual C++ Redistributable** → ошибка `DLL load failed` у onnxruntime.
  Установите: `winget install Microsoft.VCRedist.2015+.x64`.
- **Модель `medium` долго качается** с HuggingFace и может «зависнуть» при
  первом запуске. По умолчанию `run.bat` использует уже скачанную **`small`** —
  она грузится мгновенно. На `medium` переходите, только когда она докачается.

> **Локальный ИИ для протокола (по желанию).** Чтобы строить протокол оффлайн,
> установите [Ollama](https://ollama.com), затем создайте настроенную модель
> двойным кликом по **`make_protocol_model.bat`** (она скачает базовую
> `qwen2.5:7b` и соберёт из неё `vtx-protocol`). `run.bat` сам поднимет Ollama
> при старте. Без Ollama можно подключить облачный движок по ключу прямо в
> интерфейсе.

## Запуск как программы (десктоп-версия)

То же самое приложение можно запускать **в отдельном окне, как обычную
программу** — без браузера. Десктоп-версия живёт в ветке **`desktop`** (код
`app/` там идентичен веб-версии, отличается только обёртка).

**Запустить из исходников:**
```bat
git checkout desktop
install.bat
.venv\Scripts\python -m pip install -r requirements-desktop.txt
run_desktop.bat          :: откроется отдельное окно-программа
```

**Собрать установщик (.exe), как у обычных программ:**
```bat
build_desktop.bat        :: соберёт dist\VoiceTranscriber\VoiceTranscriber.exe
:: затем откройте installer.iss в Inno Setup (jrsoftware.org/isdl.php) -> Compile
```
Готовый `VoiceTranscriber-Setup.exe` ставит программу, создаёт ярлыки и по
желанию доустанавливает Ollama + VC++ и качает модель. Подробности — в
`README-desktop.md` (ветка `desktop`).

> Ollama (~700 МБ) и модель (~4.7 ГБ) не «вшиты» в .exe — установщик ставит их
> как зависимость. Для пользователя это всё равно «один установщик → готовая
> программа».

## ИИ-движки для протокола

| Движок | Где взять ключ | Стоимость | Примечание |
|---|---|---|---|
| **Ollama** (локально) | — | бесплатно | оффлайн, без лимитов; модель `vtx-protocol` создаётся через `make_protocol_model.bat`. На CPU медленно (минуты на встречу) |
| **GigaChat** (Sber) | developers.sber.ru/studio | бесплатный лимит | работает из РФ |
| **YandexGPT** | console.cloud.yandex.ru | гранты/платно | нужен API-ключ + folder id; отличный русский |
| **Groq** (Llama) | console.groq.com | бесплатно | быстро; есть лимиты в минуту/сутки |
| **Google Gemini** | aistudio.google.com/apikey | бесплатный tier | из РФ может быть недоступен без VPN |
| **Claude** (Anthropic) | console.anthropic.com | платно | максимальное качество |

Ключи, введённые в интерфейсе, живут только в памяти и пропадают при
перезапуске. Чтобы сохранить навсегда — пропишите их в `run.bat` (см. примеры
внутри файла) или в переменных окружения Windows.

## Настройки (переменные окружения)

| Переменная | По умолчанию | Описание |
|---|---|---|
| `VTX_MODEL` | `small`* | модель Whisper: `tiny`/`base`/`small`/`medium`/`large-v3` |
| `VTX_BEAM_SIZE` | `5` | 1 = быстрее, 5 = точнее |
| `VTX_CPU_THREADS` | `0` (авто) | число потоков CPU |
| `VTX_LANGUAGE` | `ru` | язык по умолчанию |
| `VTX_MAX_UPLOAD_MB` | `2048` | лимит размера файла |
| `VTX_RETENTION_HOURS` | `24` | сколько часов хранить результаты |
| `VTX_OLLAMA` / `VTX_OLLAMA_MODEL` | `1` / `vtx-protocol` | локальный ИИ-движок (модель из `make_protocol_model.bat`; если её нет — поставьте `qwen2.5:7b`) |
| `GROQ_API_KEY` | — | ключ Groq |
| `GEMINI_API_KEY` | — | ключ Google Gemini |
| `YANDEX_API_KEY` + `YANDEX_FOLDER_ID` | — | YandexGPT |
| `GIGACHAT_AUTH_KEY` | — | Authorization key GigaChat |
| `ANTHROPIC_API_KEY` | — | ключ Claude |
| `VTX_DIARIZATION` + `HF_TOKEN` | `0` | разбивка по говорящим (см. ниже) |

\* `run.bat` задаёт `VTX_MODEL=small` (мгновенная загрузка). В `config.py`
дефолт — `medium`; переключайтесь на него, когда модель докачается.

## Кто говорил (диаризация) — опционально

По умолчанию выключена (требует тяжёлых пакетов и токена). Чтобы включить:
```bat
:: в окружении проекта
pip install pyannote.audio torch
:: затем в run.bat:
set HF_TOKEN=hf_ваш_токен
set VTX_DIARIZATION=1
```
Плюс примите условия моделей `pyannote/speaker-diarization-3.1` и
`pyannote/segmentation-3.0` на huggingface.co. На CPU работает медленно;
проставляет метки «Спикер 1 / 2 …» (имён не знает).

## REST API

```bash
# создать задачу (только распознавание)
curl -F "file=@meeting.mp3" -F "language=ru" http://localhost:8000/api/jobs
# с протоколом: добавьте -F "analyze=true" -F "provider=ollama"
# -> {"job_id":"abc123...","status":"queued",...}

curl http://localhost:8000/api/jobs/abc123                       # статус
curl "http://localhost:8000/api/jobs/abc123/result?format=txt"   # текст
curl "http://localhost:8000/api/jobs/abc123/result?format=docx&provider=ollama" -o протокол.docx
```
Управление: `POST /api/jobs/{id}/pause` · `/resume` · `/cancel` ·
`/reanalyze?provider=...`.

## История изменений

**Запуск и стабильность**
- 🖥 **Десктоп-версия** (ветка `desktop`): приложение запускается **отдельным
  окном-программой** (pywebview + WebView2), а не во вкладке браузера. Есть
  сборка в `.exe` (PyInstaller) и установщик (Inno Setup), который ставит
  программу и при желании — Ollama с моделью.
- 🧠 **Настроенная локальная модель `vtx-protocol`** (`make_protocol_model.bat`
  + `Modelfile`): вшитый system-промпт, низкая `temperature` и увеличенное
  контекстное окно (`num_ctx 12288`) — стабильнее формат и больше не теряются
  детали/задачи из конца длинной встречи.
- 🛠 Исправлен запуск распознавания: переход на **Python 3.12**
  (на 3.14 движок падал), пин **`ctranslate2==4.4.0`** (сборка 4.8.0 вызывала
  access violation при загрузке модели), `setuptools<80` и авто-установка
  **Visual C++ Redistributable** (нужен для onnxruntime/VAD).
- По умолчанию используется уже скачанная модель **`small`** — больше нет
  «вечной загрузки» на 0% из-за медленного скачивания `medium`.

**Протокол встречи (ИИ-анализ)**
- 📄 Режим **«Протокол встречи»**: автоматический Word-документ — о чём шёл
  разговор, **подробный разбор по темам**, ключевые мысли, **выводы**,
  **решения и договорённости**, «сделано», **задачи с ответственными** (таблицей)
  и мелкие задачи.
- 🧩 Анализ **всей** длинной встречи целиком (разбиение на части map-reduce) —
  мелкие и поздние задачи больше не теряются.
- 🤖 Шесть ИИ-движков: **Ollama** (локально), **GigaChat**, **YandexGPT**,
  **Groq**, **Google Gemini**, **Claude**.
- 🔑 Подключение платного/облачного движка **по API-ключу прямо в интерфейсе**
  (ключ проверяется живым запросом и хранится только в памяти).
- 🔄 **Перегенерация** протокола другим движком без повторного распознавания;
  протокол каждого движка сохраняется отдельным файлом для сравнения.
- ✍️ **Кастомные инструкции** для ИИ и **экспертный режим** (полная замена
  промпта).
- ⚙️ Обработка лимитов Groq (429) и обход блокировки Cloudflare.

**Распознавание и интерфейс**
- ⏸ **Пауза / Продолжить / Отмена** во время распознавания; при отмене
  распознанная часть сохраняется.
- 🗂 Результаты хранятся **24 часа** и переживают перезагрузку страницы.
- ⏱ Корректные прогресс и таймер; индикатор «Загрузка модели…» вместо
  «зависшего» 0%.
- ⚠️ Подтверждение перед закрытием вкладки, пока задача в работе.

## Как это устроено (кратко)

- **faster-whisper** — распознавание речи (CPU, int8), модель грузится один раз.
- **Одна задача за раз** (один фоновый воркер) — чтобы не перегружать машину.
- **FastAPI** — веб-сервер и REST API; интерфейс — одна HTML-страница.
- **Анализ** (`app/analyze.py`) шлёт транскрипт выбранному ИИ-движку
  (`app/llm.py`), длинные встречи разбиваются на части (map-reduce), чтобы
  ничего не терялось; результат рендерится в Word (`app/docx_export.py`).
- Данные (загрузки, результаты, статусы задач) хранятся локально и
  авто-очищаются через сутки.
