# Автозапись встреч Телемост → облако → протокол

Цель: приложение само следит за задачами о встречах в **Weeek**, в назначенное
время **бот заходит в Телемост и записывает** встречу, после завершения
**выгружает запись в облако** (Google Drive / Яндекс Диск / локально — на выбор),
затем прогоняет её через уже существующий конвейер **распознавание → протокол**.

Работает на **отдельном сервере 24/7**.

## Главное ограничение
У Яндекс Телемоста нет публичного API для ботов. Поэтому запись делает
**бот-участник**: headless-браузер (Playwright/Chromium) заходит по ссылке гостем,
а звук+экран пишутся локально через ffmpeg. На Linux-сервере это требует
виртуального дисплея (Xvfb) и виртуального аудио-устройства (PulseAudio null-sink),
куда выводится звук вкладки. Это самая хрупкая часть: Телемост может требовать
вход, капчу или менять вёрстку — поэтому у неё всегда есть ручной фолбэк
(залить файл вручную) и подробные логи.

## Компоненты (модуль app/automation)
1. **settings.py** — постоянное хранилище настроек/токенов на диске
   (DATA_DIR/automation.json): токен Weeek, выбранное облако и его доступы,
   параметры опроса и бота. Нужно, т.к. сервер работает без человека и не может
   каждый раз переспрашивать ключи. [готово в фазе 1]
2. **weeek.py** — клиент Weeek API: список задач на ближайшее окно, чтение задачи,
   извлечение ссылки на Телемост и времени начала встречи. [готово в фазе 1]
3. **clouds/** — загрузчики: Google Drive, Яндекс Диск, локальный диск; общий
   интерфейс upload(file, name) → ссылка. [фаза 2]
4. **recorder.py** — бот: Playwright заходит в Телемост, ffmpeg пишет A/V,
   определяет конец встречи (все ушли / ведущий завершил), отдаёт mp4. [фаза 3]
5. **scheduler.py** — оркестратор: периодически опрашивает Weeek, на каждую
   встречу ставит задачу «записать в момент T», по окончании запускает
   recorder → upload в облако → существующий transcribe+analyze → (опц.)
   прикрепляет протокол обратно в задачу Weeek. [фаза 4]
6. **UI** — вкладка «Автоматизация»: токен Weeek, выбор облака и его подключение,
   список ближайших встреч, статусы записей, кнопка «записать вручную». [фаза 5]

## Поток данных
Weeek task (ссылка + время) → scheduler ждёт T → recorder пишет mp4 →
clouds.upload → jobs.submit(mp4, analyze=True) → docx-протокол →
(опц.) комментарий со ссылкой в задачу Weeek.

## Настройка рекордера на Windows (фаза 3)
1. `pip install playwright` затем `playwright install chromium`.
2. ffmpeg в PATH (или укажите `ffmpeg_path`). Проверка: `ffmpeg -version`.
3. Звук встречи нужно отдать в loopback-устройство, которое пишет ffmpeg:
   - вариант А: включить «Стерео микшер» (Stereo Mix) в устройствах записи;
   - вариант Б: поставить VB-CABLE и сделать его устройством вывода по умолчанию.
   Затем выбрать это устройство в настройке `audio_device`
   (список — `GET /api/automation/recorder/audio-devices`).
4. Режим входа `auth_mode`: `guest` (по ссылке) или `profile`. Для `profile`
   один раз войдите в Яндекс: `POST /api/automation/recorder/login`.
5. Проверка: `POST /api/automation/recorder/test {url, seconds}` — бот зайдёт и
   запишет несколько секунд; вернёт путь к файлу и логи. Селекторы Телемоста,
   скорее всего, придётся подправить под текущую вёрстку (в браузере есть
   скриншот при неудачном входе).
