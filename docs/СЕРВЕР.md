# Установка на сервер (Ubuntu/Debian)

Пошагово: от «репозиторий склонирован» до «сайт работает по IP».

---

## 0. Что понадобится
- Ubuntu 22.04 / 24.04 (или Debian), **Python 3.10–3.12** (3.14 не подходит:
  ломает ctranslate2/onnxruntime). Проверить: `python3 -V`.
- **ОЗУ:** модель `medium` — ~1.5 ГБ, `large-v3` — ~3 ГБ во время распознавания.
  Если планируете локальный ИИ для протоколов (Ollama) — плюс ~5 ГБ.
  Минимум комфортно: 8 ГБ. На 4 ГБ ставьте модель `small` и облачный движок.
- Диск: ~5 ГБ под модели + место под записи встреч.

## 1. Установка одной командой
```bash
cd ~/voice-transcriber
bash deploy.sh
```
Скрипт сам: поставит системные пакеты (ffmpeg, libgomp1, tzdata), создаст
`.venv`, установит зависимости, скачает модель распознавания и предложит
поставить автозапуск (systemd) — уже с вашим пользователем и путём.

Полезные переключатели:
```bash
VTX_MODEL=small bash deploy.sh          # модель полегче (мало ОЗУ)
PORT=8080 bash deploy.sh                # другой порт
WITH_OCR=1 bash deploy.sh               # + распознавание текста с экрана
WITH_PLAYWRIGHT=1 bash deploy.sh        # + браузер для бота (см. раздел 6)
```

## 2. Открыть порт
Двух мест обычно достаточно:
```bash
sudo ufw allow 8000/tcp        # если на сервере включён ufw
```
И **в панели облака** (Yandex Cloud — «Группы безопасности» вашей ВМ) добавить
входящее правило: TCP, порт `8000`, источник — ваша сеть или `0.0.0.0/0`.
Без этого правила сайт не откроется, даже если сервис запущен.

> ⚠️ По HTTP без пароля сайт доступен всем, кто знает IP. Если это не закрытая
> сеть — ограничьте источник в группе безопасности своим офисным IP либо
> позже поставим домен + HTTPS (nginx + Let's Encrypt).

## 3. Проверить, что работает
```bash
systemctl status voicetx          # должно быть active (running)
curl -s localhost:8000/healthz    # {"ok":true,...}
hostname -I                       # узнать IP сервера
```
Открыть в браузере: `http://<IP сервера>:8000/`

Управление сервисом:
```bash
sudo systemctl restart voicetx    # перезапуск
sudo journalctl -u voicetx -f     # живые логи
```

## 4. Настроить движок для протоколов
Распознавание работает сразу и без ключей. Для **протокола** нужен ИИ-движок —
на выбор:

- **Облачный (проще, быстрее):** на главной странице выбрать движок (Groq /
  YandexGPT / GigaChat / Gemini / Claude) и подключить ключ прямо в интерфейсе.
  ⚠️ Ключи ядра хранятся **в памяти** — после перезапуска сервиса их надо
  ввести заново. Чтобы держались постоянно, пропишите их в unit-файле:
  ```bash
  sudo systemctl edit voicetx      # добавить: Environment=GROQ_API_KEY=...
  sudo systemctl restart voicetx
  ```
- **Локальный (приватно, без интернета):** установить Ollama, нужно ~5 ГБ ОЗУ.
  ```bash
  curl -fsSL https://ollama.com/install.sh | sh
  ollama pull qwen2.5:7b
  ```

## 5. Обновление кода на сервере
```bash
cd ~/voice-transcriber
git pull
.venv/bin/pip install -r requirements.txt      # если менялись зависимости
sudo systemctl restart voicetx
```

Если репозиторий переехал на Яндекс SourceCraft — переключить адрес:
```bash
git remote set-url origin <URL репозитория в SourceCraft>
git pull
```

## 6. Автозапись встреч на Linux — пока НЕ работает
Захват экрана сейчас реализован только под Windows (`ffmpeg gdigrab` + `dshow`).
На Linux нужен отдельный бэкенд: **Xvfb** (виртуальный экран для браузера-бота),
`x11grab` для видео и **PulseAudio null-sink** для звука встречи.

Пока этого нет, на сервере работают: загрузка файла → распознавание → протокол,
а также вся часть Weeek (список встреч, расписание). Саму запись можно делать
на Windows-машине или загружать файл вручную.

Когда Linux-бэкенд будет добавлен, дополнительно понадобится:
```bash
sudo apt-get install -y xvfb pulseaudio
WITH_PLAYWRIGHT=1 bash deploy.sh
```

## 7. Если что-то не так

**Сервис не стартует** → `sudo journalctl -u voicetx -n 50`.
Частое: не тот Python (нужен 3.10–3.12), не установлен `libgomp1`.

**Сайт не открывается снаружи, но `curl localhost:8000` работает** → закрыт порт:
проверьте группу безопасности в облаке и `sudo ufw status`.

**«Загрузка модели…» висит несколько минут** → первая загрузка модели качает
файлы (large-v3 ~3 ГБ). Дальше быстро. Можно скачать заранее:
`VTX_MODEL=large-v3 bash deploy.sh`.

**Убит по памяти (OOM)** → в логах `Killed`. Возьмите модель полегче
(`VTX_MODEL=small`) и не ставьте жёсткий `MemoryMax` в unit-файле.

**Время встреч сдвинуто** → в настройках автоматизации проверьте часовой пояс
(`Europe/Moscow`); на сервере — `timedatectl`.
